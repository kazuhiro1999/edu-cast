# 検証計画とマイルストーン

## フェーズ 0: 技術検証（2週間）

目的: 「Web スタックで毎日1本を無人で出せるか」を 10 秒のサンプルで確定する。

| # | 検証 | 合格条件 |
|---|---|---|
| 1 | Remotion template-three に VRM を読み、`useCurrentFrame` で VRMA と `aa` を駆動して 10秒レンダ | `--gl=angle`（ローカル GPU）で実時間の 3倍以内、`swangle`（CPU）でも完走 |
| 2 | Irodori-TTS 出力 + pydomino で母音時刻 → 口パク | 目視で「あいうえお」が合っている。VOICEVOX（モーラ時刻つき）と遜色ない |
| 3 | Irodori-TTS 重みのライセンス確認 | 商用可の根拠 URL を docs に記録。不可なら代替を決める |
| 4 | YouTube API プロジェクト作成・OAuth・審査申請 | 申請完了（結果待ちは並行） |
| 5 | 板書4型の React コンポーネント | 実機で右 192px・下 672px に被らない |
| 6 | 台本 JSON スキーマ（zod）と JSON→Ink 変換、inkjs コンパイル検証 | A 型・B 型の台本 3本ずつが機械的に通る |

不合格なら: 1 が遅すぎる→クラウド GPU（RunPod 等、数円〜数十円/本）かローカル GPU 常駐。2 が不自然→Qwen3-ForcedAligner / MFA を試し、それでも駄目なら uLipSync（Unity）に切替。

## フェーズ 1: パイロット（4週間、非公開〜限定公開）

- キャラ1体（VRoid → VRM）、モーション6種（talk / idle / point / think / happy / nod）、表情5種。
- A 型（1問1答）× 10本、B 型（用語解説）× 10本を作る。ユニットはセキュリティ・ネットワーク・DB から。
- 人のレビュー時間を計測。目標 15分/本以下。
- 友人・社内の 5〜10 人に見せ、「冒頭3秒で止まるか」「AI 音声が気になるか」「板書が読めるか」を聞く。
- 概要欄テンプレ（AI 開示・クレジット・出典・長尺リンク）を固定。

## フェーズ 2: 公開運用（12週間）

- 毎日1本（週7）、曜日固定。
- KPI: Viewed 75%、APV 70%、登録者転換。週次で topic queue の優先度に反映。
- 4週目: 時事レーン（B）を開始。一次情報が出てから 48時間以内のルール。
- 8週目: Shorts 5本 → 10分の長尺講義を自動合成し、週1で公開。関連動画リンクで Shorts から誘導。
- 12週目: 拡充版 YPP（登録者 500・90日に3本・Shorts 300万回/90日 or 3,000時間）の到達状況で判断。

## フェーズ 3: 新試験への移行（2027年前半）

- IPA の新制度の詳細（開始日・シラバス確定版）に合わせ、「新試験サンプル問題を解く」「シラバス案を読む」シリーズを先行投入。
- 「最後の応用情報（2027-02）」回を時事として投下。
- 再生リストを試験名ではなくトピック名で維持し、Shorts series 機能が来たらシーズン化。

## 判断ポイント（Go / No-Go）

| 時点 | 問い | No の場合 |
|---|---|---|
| フェーズ 0 終了 | 無人で 1本/日が出せるか | Unity（ScenarioXR）Standalone レンダラに切替、または半自動運用 |
| フェーズ 1 終了 | レビュー 15分/本以下か。AI 音声が致命的でないか | TTS を変える。台本の出典フィールドを強化 |
| フェーズ 2 の 8週目 | 登録者が週単位で増えているか | フォーマット（型・尺・キャラのショット）を変えて 4週再試行。トピックは変えない |
| フェーズ 2 終了 | 継続する価値があるか | パイプラインを B2B（企業研修向け自動解説動画）の商材として整理し、チャンネルはショーケースに縮小 |
